# 项目线

学生做课设、毕设、竞赛之前，先查这件事有没有人做过、做到什么程度、哪部分能直接用。

## 先判断值不值得查

三问，都过才往下走：

1. **这个题目有技术实现的部分吗？** 纯文献综述、纯社会调查、纯问卷分析没有，"做一个 XX 系统 / 工具 / 算法"有。
2. **用户是不是要真做出来？** 交个报告就完事的不值，要跑起来、要演示、要答辩的值。
3. **用户有没有把技术栈定死？** 定死了也查，但查的是"这个栈下有没有现成实现"，范围更窄。

三问都不过，说明这是选题咨询不是技术落地，直接答，别硬套流程。

## 检索

按 `references/repos.md` 的方法查。最少覆盖三个来源：

1. **GitHub** — 有接口，中文关键词也能搜
2. **Gitee** — 国内课设项目多，但只能开浏览器，没有可用接口
3. **通用搜索** — 用「题目 + 毕业设计 + 源码」这类组合

关键词怎么组：

- 题目核心名词 + 技术栈：`图书管理 springboot`
- 中文搜一次，英文再搜一次：`library management system`
- 加限定词找学生项目：`毕业设计`、`课程设计`、`大作业`

## 排序：把"能不能跑"放第一位

这一节是整个项目线的核心。普通搜索按星数排，那是给工程师看的。学生要的是能跑、能读、能量身改。

| 优先级 | 看什么 | 怎么判断 |
|---|---|---|
| 1 | 能不能跑起来 | 有没有安装步骤、有没有依赖清单（`pom.xml` / `package.json` / `requirements.txt`）、有没有建库脚本 |
| 2 | 代码量读不读得完 | 仓库体积。超过 50MB 基本是工程项目，不是课设；几千行以内的才好改 |
| 3 | 依赖复不复杂 | 要不要装 Redis、消息队列、搜索引擎。学生机器跑不动三个中间件 |
| 4 | 技术栈匹配 | 用户说 Java 就别推 Python |
| 5 | 最后才看星数 | 星高的是框架不是课设。星数只说明"有人用"，不说明"适合你改" |

五个维度看完，还要补一句维护状态：最近一次提交是什么时候、issue 有没有人回。

## 输出三块

### 一、能直接用的

项目名、地址、语言、规模、最后更新时间、它完整实现了什么功能。地址必须贴出来，不能只给名字。

### 二、要改的部分

逐项说：这个项目的哪些模块能留、哪些必须换成你的、为什么换。

分三类讲清楚：

- **通用能力**：登录注册、权限、分页、文件上传、图表。这些每个课设都写一遍，直接用现成的，不要自己造。
- **要改的**：业务逻辑、数据模型、界面。这部分是你的工作量。
- **不能用的**：它特有的、跟你的题目无关的模块。直接删。

### 三、坑

这个方向学生最常踩的重复劳动、已经有成熟方案的地方。

写的时候具体，不要写"注意性能"这种空话。要写"这个项目用了 Redis 做缓存，你没装 Redis 就跑不起来，先在配置里关掉"。

## 创意查重

用户担心选题烂大街时做这一步。

做法：把题目拆成 2-3 个功能关键词，各搜一次，取最接近的 5 个项目。

输出三样：

1. 每个项目覆盖了什么功能
2. 它没做什么（这是你能下手的地方）
3. 你的题目跟它重叠在哪

**不给相似度百分比。** GitHub 搜索是关键词匹配，算不出语义相似度。写一个"相似度 73%"就是编的，比不给更糟。

结论只写一句：这个方向已经做到哪一步，你的差异点只能放在哪。

## 七条硬规则

1. **推荐的项目必须真的能打开。** 地址贴出来，打不开的删掉，不要凭印象写仓库名。
2. **不能跑的不算推荐。** 没有说明、没有依赖清单、只丢一个压缩包的，标成"仅参考思路"，放在最后。
3. **不替你写代码。** 给路线、给模块划分、给要改的地方。代码让 AI 写完，答辩你讲不出来。
4. **不推荐整包照抄。** 说清哪些是通用能力（用现成的），哪些是你的工作量（自己写）。
5. **星数不是适配度。** 见上面的排序表。
6. **维护状态要说。** 半年没提交的项目照样能推，但要写清"这个项目 2024 年之后没更新"。
7. **查两次没结果就停。** 说明这个方向确实少人做。这本身是好消息，直接告诉用户。

## 需要打断的两种情况

- 题目太宽（"做一个管理系统"），先问清管理什么、给谁用
- 用户想要"能直接交的完整代码"，先说明这条线只给路线，不给成品

## 工作量估计

给粗估，不要精确到天：

- 骨架能不能用：能直接用 / 要改一半 / 只能参考思路
- 主要工作量在哪：前端 / 后端 / 数据库 / 算法 / 部署
- 最容易超期的是哪一步

学生最不会估时间。给他一句"这块大概两周，最容易卡在环境配置上"，比给他一个路线图有用。
